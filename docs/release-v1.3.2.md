# v1.3.2 — 视觉塔提速 4.3×、识别可控、目录批处理、无头 CLI

> 本版相对 v1.2.0 是一次大跨度的「性能 + 可控性 + 工程」更新。
> 核心变化：**CPU 上单页识别从约 120 秒降到约 19 秒**（视觉编码改 fp32，输出逐字节一致）。

## 亮点

- **CPU 提速约 4.3×**：真机交错 A/B 显示视觉塔 bf16 在这类 x86 上走仿真路径，
  prefill 47.3 s → 10.9 s，同一页端到端 120.3 s → 18.8 s，输出逐字节相同。
  CUDA 上仍用 bf16；带原生 bf16（AVX512-BF16/AMX）的新 CPU 可用
  `OCRMIT_VISION_DTYPE=bf16` 回退。
- **识别可控**：单页生成上限（默认 4096 token）、合并页数上限（默认 20 页，
  超出自动分组、组间可取消）；输出被截断或页数不符时，界面明确提示
  「期望 N 页、实际 M 页」并告诉你该调哪个参数。
- **整目录识别**：选文件夹即批量入列（后端直读路径，不上传、不占临时盘）；
  批量失败项可展开完整错误并「只重跑失败项」。
- **无头 CLI**：`python cli.py --input <文件/目录> [--json]`，退出码 0/1/2/3。
  仅承诺源码运行（打包版 `console=False`，无控制台），详见 `docs/cli.md`。
- **安全**：结果区的 Markdown 渲染改为白名单重建 + CSP，关掉「恶意文档被 OCR
  转写后执行脚本」的通道（该脚本可越过本机 API 边界）。
- **工程**：503 条回归用例（零第三方依赖）、静态体检 `tools/check.py`、
  GitHub Actions 门禁、依赖锁文件、一条命令出包、月志轮转、设置损坏自愈。

## 修复

| 问题 | 说明 |
|---|---|
| 源码运行无法加载模型 | venv 里装了 torch 也会被「请先下载推理引擎组件」挡住（组件守卫只认冻结版） |
| 分卷续传产坏包 | 取消/被杀后分卷按「文件存在」跳过，可能永久坏包；改为暂存名 + 大小核对 |
| 断线刷栈 | 关窗/刷新时稳定打印一整段 `ConnectionAbortedError` |
| 组件切换必失败 | 运行中 CPU→CUDA 覆盖已加载的 DLL 报 PermissionError，且残留 3.5 GB；现提前提示「重启后再换」并清理安装包 |
| 自动加载挡窗口 | 模型就绪时双击后 20.1 s 才出窗口 → 改到建窗回调，窗口 3.4 s 出现 |
| 6 GB 显卡「能跑但更慢」 | 显存不足时权重挤到共享内存（长图 1.6 tok/s）；`自动` 现按显存回落 CPU |
| 长截图被压坏 | 「长截图自动降 base」会把超高图压到文字不可读、模型开始编造甚至重复；已回退为上游语义（单图 gundam / 多页 base） |
| 假按钮与死功能 | 「卸载模型」无对应 API；界面缩放因全站 0 rem 而完全无效；6.8 GB 下载无取消 |
| settings.json 被写成 CRLF / 损坏即清空 | 现在 LF 写入、坏文件隔离为 `.corrupt-<ts>` 并保留 `.bak` |
| SSE 队列无界 | 一个不消费的订阅者能把内存吃到 2 万条；现在 256 条上限 + status 合并 |
| 首屏等外域字体 | 去掉 `fonts.googleapis.com`，与「数据不出本机」一致，断网也能立刻可用 |

## 已知限制

- **显存 < 8 GB 的 NVIDIA 卡**：能加载但性能悬崖（实测 GTX 1660 SUPER 6 GB 长图
  1.6 tok/s），`自动` 会回落 CPU；显式选 CUDA 仍尊重你的选择。
- **打包版不含 CLI**：`console=False` 没有控制台可写，CLI 只支持源码运行。
- **GPU OOM 路径未实测**：本机未触发 OOM，无法确认真实 OOM 时的提示与回退行为。
- **EXE 无版本资源文件**：右键属性里看不到版本号（不影响运行）。

## 升级提示

- 从 v1.2.0 升级：直接替换程序目录即可，`settings.json` / `models/` / `outputs/`
  不受影响（会自动补 `settingsVersion`）。
- **更换推理引擎组件（CPU↔CUDA）需要先退出程序**，否则会提示「需要重启」。
- 模型权重仍是 `baidu/Unlimited-OCR-2`（约 6.8 GB），未变化。
